The human relay is the problem.

AI can already explain what to do. The frustrating part is still you moving commands, error logs, files, and machine state between the chat and the place where work actually happens.

No command copy-paste

Real result verification

“Done” is not enough. Meaningful actions should finish with an observable check when the target can be verified.

Your machines, one model

What should this feel like?

The target is not another dashboard. It is the AI interface you already use gaining a safe path to real work.

“Check this server and fix the failing test.”

Inspect allowed files, run bounded commands, make the permitted change, then verify the test result.

“Do this on my phone.”

Android itself becomes an independent work node. Android/Termux is now a verified public node. Media and device-control modules are the next Android expansion.

“Continue the job and tell me when it is actually done.”

Long-running resume and continuity are planned around the same verified-result principle.

Power without an open shell to the Internet.

Machine access is a trust problem, so safety has to be visible to the user rather than hidden in architecture diagrams.

Explicit roots Bounded actions shell=false Secret-path denial Atomic writes Open source Self-hostable core\nOfficial tunnel-client SHA256 verified

The current local HTTP endpoint binds to loopback by default. Do not expose an unauthenticated local endpoint directly to the public Internet.

We need real users more than more hidden features.
